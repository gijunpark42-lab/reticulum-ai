## evidence.json schema

```json
{ "generated": "2026-09-06",
  "entries": {
    "5b1395e8a335588d": {
      "doc":       "transcripts/av/nvidia_q3_2027.txt",     // repo-relative, forward slashes; null when no_source
      "excerpt":   "…context «$57 billion» context…",       // verbatim source text, whitespace collapsed,
                                                            //   ±220 chars cut on word boundaries, match in «…»,
                                                            //   "…" marks a cut edge; null when nothing found
      "matched":   "$57 billion",                           // the text inside «…»; null when nothing found
      "status":    "found" | "no_match" | "no_source",
      "via":       "number" | "phrase" | "words" | "counterparty" | null,   // EXTRA key: what anchored the match
      "unmatched": ["45", "3.2"]                             // EXTRA, optional: figure/units/value numbers absent from the doc
    } } }
```

Two keys beyond the brief: `via` (so the UI can say "number located" vs "wording located" vs
"counterparty named") and `unmatched` (verify_graph's `numbers_missing`, so a "found" entry whose
other numbers are missing still shows an amber note). Both optional; ignore them if unwanted.

The corpus contains no `«`/`»` of its own (grep-checked), so splitting the excerpt on `«…»` is safe.

## Key format (Python and TypeScript agree byte for byte)

```
key = sha1( utf8( kind + "|" + company + "|" + target + "|" + label + "|" + signal ) ).hexdigest()[:16]
```
- `kind` — `"qd"` (node quarterly_data entry) or `"contract"` (edge contract)
- `company` — node id; for a contract the edge **source** company
- `target` — edge **target** company; `""` for qd
- `label` — `quarter` (qd) / `source` (contract), exactly as stored
- `signal` — the entry's `signal` text, exactly as stored — no trim, no case-fold
- Python: `evidence.entry_key(kind, company, target, label, signal)`;
  TS: `entryKey(kind, company, target, label, signal)` in `web/src/lib/evidence.ts`.
- Verified: all 2,475 graph entries hashed in Node (compiled `evidence.ts`) match the Python keys
  (0 mismatches; 614 rows contain non-ASCII). `evidenceSelfCheck()` embeds sha1("abc"), sha1(""),
  and two Python-computed project keys (one with `→ 조 억원 — “ ”`).
- Entries stored in two chain files produce the same key (2,475 entries → 2,467 unique keys). Fine.

Right after `derive_all(graph)` and BEFORE the `--sync` block (so `npm run sync` copies the fresh file):
```python
    from evidence import build_evidence; build_evidence(graph)   # graph → graph/evidence.json (source excerpt per data point, ~25 s)
```
`build_evidence(graph)` reuses the dict `build_graph()` returned; it re-reads `graph/merged_graph.json`

`verify_graph.py` is why it is not shared).

## How the excerpt is chosen (deterministic, no model)

1. SOURCE — `verify_graph.resolve_label` (header label → filename join → loose event match). One extra
   fallback of mine: a graph label `… DART supply contract (date)` is first tried against the Korean
   header spelling `… DART 공급계약 (date)` (see caveats). No file → `no_source`.
2. NUMBERS — `verify_graph.numbers_in(figure, units, value)` minus date fragments (`08-14-2026`) and
   leading-zero tokens. Every occurrence via the four `Doc.has_number` rules, position-aware: exact,
   trailing-zero, rounded, unit-rescaled (digit-run prefix, plus "integer amount that rounds to the
   figure once divided by 10 / 10³ / 10⁶ / 10⁹" — `KRW 422.5B` ↔ a filing's `422,483` 백만원).
   Each candidate scores: distinctive signal words within ±220 chars (corpus IDF minus a 0.75 floor,
   so words in > ~half the documents weigh nothing; a small English→Korean glossary lets `backlog`
   count `수주…` inside DART filings) + specificity of the matched token (`48` → 0, `150,323` → 3)
   + 1.0 per other figure number found exactly in the same window (0.5 if loosely) − 0.5 for a
   rounded/rescaled match. Numbers present but none found → `no_match` (nearest wording passage,
   if any, still attached as context).
3. WORDING (no numbers) — best-weighted run of 4–6 consecutive signal words present in the doc, then
   3–2 words, then a single rare word with another signal word in the window (`via: "words"`), then
   the counterparty's name / Korean alias (`via: "counterparty"`, mirrors verify_graph's PARTY check).
   Numbers in the signal text itself are a last resort and must have a distinctive word nearby.
4. The filer's own name never anchors or scores a passage; file headers (`# source label:`,
   `SOURCE:`/`CALL DATE:` lines, Motley Fool date lines) are excluded from matching.
